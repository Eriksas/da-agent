# 数据看板设计

## 1. 步骤（按顺序执行）

1. **明确读者和问题**：看板给谁看、他要靠它判断什么。写进方案的 goal。没有指定读者时，默认给业务负责人看整体情况。
2. **了解数据**：调用 `profile_table`。看清哪些是时间列、数值列、分类列、编号列；逐条读 rules。
3. **定指标和口径**：每个指标写清对哪一列做什么聚合、用 where 限定什么。例如电商的 GMV 是 `sum(amount)`、where `line_type = 销售`；订单数是 `count_distinct(invoice)`。比率用 ratio 引用两个基础指标。
4. **选图**：按第 2 节的规则，一般 6–9 张图，其中 2–4 张 kpi。
5. **预览**：每张图都用 `preview_chart` 看一遍，读 notes。
6. **处理陷阱**：对照第 3 节逐条检查。
7. **写 why 和 insight**：why 写这张图回答哪个业务问题；insight 写一句数据显示了什么，数字照抄预览结果。
8. **提交**：调用 `submit_dashboard`。退回就逐条改，改完提交完整方案。

## 2. 选图规则

| 要回答的问题 | 用什么图 |
|---|---|
| 最重要的几个数是多少 | kpi（每张一个数） |
| 随时间怎么变化 | line（可按 series 分几条线）或 column（单个指标，按月） |
| 随时间的构成（谁贡献了多少） | stacked_column（最多 4 段，指标要能相加） |
| 哪些类别最大 | bar + top_n |
| 两个周期维度的分布（星期 × 小时） | heatmap |
| 多个指标对照（例如各公司的几项比率） | table |

- 一张图只放一个指标，不做双坐标轴；两个量纲不同的指标拆成两张图。
- 排名、构成用能相加的指标（sum、count）；平均、比率、去重计数不能堆叠，也不能把各组加起来当合计。
- 筛选器最多 2 个，每个不超过 6 个取值；取值多的列用 keep 合并（例如只保留最大的国家，其余合并成“海外”）。

## 3. 陷阱清单（提交前逐条对照）

| 陷阱 | 怎么发现 | 怎么处理 |
|---|---|---|
| 最后一个周期不完整 | notes 里写“只覆盖了部分时间” | insight 不拿它和完整周期比；在 notes 里写明 |
| 一家独大 | notes 里写某个分组占 60% 以上 | 用 keep 把它单独分开，或再放一张只看其余分组的图；insight 写出它的占比 |
| 把不同的东西加在一起 | profile 的 rules（line_type、item） | where 限定一个取值，或按它分组 |
| 不同单位放在一起 | profile 的 rules（currency）；提交时被退回 | 比率（ratio）可以跨公司比；金额按公司分开看或用筛选器 |
| 去重计数不能相加 | 指标是 count_distinct | 热力图、分组的格子加起来会比总数多（一张订单可能跨两个小时），insight 不写格子之和 |
| 下单口径含取消 | 电商的销售行包含之后被取消的订单 | 同时放取消金额或取消率，或在 notes 里说明 |
| 缺失值 | profile 的 null_share（例如 customer_id） | 按客户统计的指标会偏少，在 notes 里写明 |

## 4. insight 写法

- 一句话，写数据显示了什么：最高、最低、占比、最近一期的变化。
- 数字照抄预览结果，带上时间和单位，例如“2011-11 的 GMV 最高，为 1,452,116.38”。
- 不写原因，不写建议；看不出明显结论时可以留空。
