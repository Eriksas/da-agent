# 数据看板设计

## 1. 步骤（按顺序执行）

1. **明确读者和问题**：看板给谁看、他要靠它判断什么。写进方案的 goal。没有指定读者时，默认给业务负责人看整体情况。
2. **了解数据**：调用 `profile_table`。看清哪些是时间列、数值列、分类列、编号列；逐条读 rules 和 row_identity（一行代表什么）。
3. **定指标和口径**：每个指标写清对哪一列做什么聚合、用 where 限定什么。例如电商的 GMV 是 `sum(amount)`、where `line_type = 销售`；订单数是 `count_distinct(invoice)`。比率用 ratio 引用两个基础指标。
4. **选图**：按第 2 节的规则，一般 6–9 张图，其中 2–4 张 kpi；**最多 9 张（含 kpi），超过会被退回**。成对的图（分布 + 各段比率）也算两张，图多时先删最不重要的。先想清楚每张图要回答的问题，再按问题选图型，不要每次都是条形图加表格。
5. **预览**：每张图都用 `preview_chart` 看一遍，读 notes。
6. **处理陷阱**：对照第 3 节逐条检查。
7. **写 why 和 insight**：why 写这张图回答哪个业务问题；insight 写一句数据显示了什么，数字照抄预览结果。
8. **提交**：调用 `submit_dashboard`。退回就逐条改，改完提交完整方案。

## 2. 选图规则

| 要回答的问题 | 用什么图 |
|---|---|
| 最重要的几个数是多少 | kpi（每张一个数） |
| 随时间怎么变化 | line（可按 series 分几条线）或 column（单个指标，按月） |
| 随时间的构成（谁贡献了多少） | stacked_column（最多 4 段，指标要能相加） |
| 哪些类别最大（合计） | bar + top_n |
| 各分组的比率、平均值谁高谁低 | bar（类别多）或 column（类别有先后，如月份）+ `reference: overall`，一眼看出谁高于整体 |
| 规模和比率一起看（哪些来源量大但转化低） | scatter：metrics 写 [规模指标, 比率指标]，加 `reference: overall`；不要用“数量 + 比率”的表格 |
| 数值列的分布（浏览了多少页、通话多长） | column + `x.bins`（分界点从小到大），指标用 count |
| 数值越大，比率越高吗 | column + `x.bins`，指标用比率，加 `reference: overall` |
| 两个周期维度的分布（星期 × 小时） | heatmap |
| 查具体的数（多个指标的明细） | table，最多 1 张 |

- 一张图只放一个指标，不做双坐标轴；两个量纲不同的指标拆成两张图。
- 排名、构成用能相加的指标（sum、count）；平均、比率、去重计数不能堆叠，也不能把各组加起来当合计。
- 筛选器最多 2 个，每个不超过 6 个取值；取值多的列用 keep 合并（例如只保留最大的国家，其余合并成“海外”）。

**让每张图有重点**：

- 写了 insight 的 bar、column、scatter，用 `highlight` 标出 insight 里提到的 1–3 个分组（照抄预览的 x），其余自动变灰。读者先看到的就是结论说的那几个。
- 比率、平均值的对比都加 `reference: overall`（程序画整体值的虚线，预览的 facts.reference 里有这个值，可以写进 insight）；sum、count 这类合计不加。
- 6 张以上的图按读者的问题分成 2–4 个 `section`（例如“整体”“客群”“渠道”“时间”），每张非 kpi 的图都写；kpi 不写。
- 两张一起看的小图可以都写 `width: half` 并排，例如分布和各段的比率；重要的图占整行。

## 3. 陷阱清单（提交前逐条对照）

| 陷阱 | 怎么发现 | 怎么处理 |
|---|---|---|
| 最后一个周期不完整 | notes 里写“只覆盖了部分时间” | insight 不拿它和完整周期比；在 notes 里写明 |
| 一家独大 | notes 里写某个分组占 60% 以上 | 用 keep 把它单独分开，或再放一张只看其余分组的图；insight 写出它的占比 |
| 把不同的东西加在一起 | profile 的 rules（line_type、item） | where 限定一个取值，或按它分组 |
| 不同单位放在一起 | profile 的 rules（currency）；提交时被退回 | 比率（ratio）可以跨公司比；金额按公司分开看或用筛选器 |
| 去重计数不能相加 | 指标是 count_distinct | 热力图、分组的格子加起来会比总数多（一张订单可能跨两个小时），insight 不写格子之和 |
| 下单口径含取消 | 电商的销售行包含之后被取消的订单 | 同时放取消金额或取消率，或在 notes 里说明 |
| 排名被取消的大单撑高 | notes 里写某个分组的销售“后来被取消”了一大半 | 类别排名改用净销售额（difference：销售 − 取消），或在 insight 里写明 |
| 缺失值 | profile 的 null_share（例如 customer_id） | 按客户统计的指标会偏少，在 notes 里写明 |
| 像缺失值的取值（unknown、未知） | profile 的 possible_missing | 在 notes 写明它的占比（例如“default 有 20.9% 是 unknown”）；比率图里它单独成组，不要当成一个真实分组下结论 |
| 不知道一行代表什么 | profile 的 row_identity：没有数据说明，也没有能唯一标识一行的列 | 按行计数的指标叫“记录数”，口径写“按记录数计算”；不断言一行是一个客户还是一次联系，也不断言同一对象会不会重复计入 |
| 分类有先后（学历、年龄段、等级） | 取值按字母排出来顺序不对 | 在 x 或 series 上用 order 写出先后；月份和星期会自动按日历排，不用写 |
| 小样本的极端比率 | 预览里比率行的 denominator 很小 | insight 写出样本量（例如“31.4%（275 / 875）”），或在 notes 提醒 |

## 4. insight 写法

- 一句话，写数据显示了什么：最高、最低、占比、最近一期的变化。
- 数字照抄预览结果，带上时间和单位，例如“2011-11 的 GMV 最高，为 1,452,116.38”。
- 比率可以带上分子和分母（预览结果里的 numerator、denominator），例如“转化率 11.3%（4,640 / 41,188）”。
- 有参考线时，可以写和整体的比较，例如“新访客 24.9%，高于整体 15.5%”；highlight 的分组和 insight 提到的一致。
- 写“越……越……”这类规律之前，逐个分组核对：只要有一个分组不符合，就只写最高和最低，不写规律。
- 写“最高、最低”之前核对整张图，包括 unknown、样本很小的分组；只在一部分分组里比较时写明范围（例如“样本 100 条以上的分组里”）。程序会核对，说错会被退回。
- 标题写“前 10”时设 `top_n: 10`，图里的分组数要和标题一致。
- 不写原因，不写建议；看不出明显结论时可以留空。
