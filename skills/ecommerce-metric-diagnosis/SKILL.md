# 电商指标异动诊断

## 1. 先判断问题属于哪一档

- **查一个数**（如“上周订单数是多少”）：调用 `metric_summary`，直接回答，不走下面的完整流程。
- **异动诊断**（默认）：按第 2 节全部步骤执行。
- **周报**：按第 2 节全部步骤执行，并使用第 5 节的输出格式。

## 2. 步骤（按顺序执行）

1. **确定分析周和基期**：调用 `metric_summary`。用户说“上周”时，用系统提示中给出的最近完整周。
2. **可比性检查**：逐条阅读 `metric_summary` 返回的 warnings（不完整周、交易天数不同、节假日、极端大额行）。
   - **危险信号**：任一核心指标变化超过 50%，先排查数据问题（极端大额行、不完整周；需要时调用 `data_quality_overview`），再解读业务。
   - 当期与基期不可直接比较时，结论第一句必须说明“不可直接比较”及原因，后续结论都要带上这个保留。
3. **拆解**：调用 `decompose_gmv`，看活跃客户数、人均订单数、客单价、缺客户 ID 部分各贡献多少。以 Shapley 值为准；默认顺序与 Shapley 相差较大时，说明结论对拆解顺序敏感。
4. **下钻**：调用 `drilldown`，至少看国家和新老客两个维度，需要时再看商品。
   - 贡献不足总变化 10% 的分组不单独展开。
   - `others` 是前 N 名以外的合计，不等于剔除某一项后的结果。
   - 订单少于 30 的分组标记为样本不足，不对它单独下结论。
5. **写结论**：先对照第 3 节的陷阱清单逐条检查，再按第 4 节的写法组织。

## 3. 陷阱清单（写结论前逐条对照）

| 陷阱 | 在本数据里的样子 | 怎么避免 |
|---|---|---|
| 不完整周期比较 | 数据最后一周只到周五中午；节假日周只有几个交易日 | 交易天数不同时，不直接比较总量，结论写明保留 |
| 极端值 | 一笔 8 万件的订单当天被全额取消，GMV 虚高 | GMV 与净销售额一起看；引用极端大额行警告 |
| 忽略抵消项 | 只说“增长全靠老客”，忽略“未知”客群的正贡献 | 列出所有正负贡献，不只谈最大的一项 |
| 口径偷换 | 把“前 N 名以外的合计”当成“剔除某一项后的结果” | 只使用工具明确给出的口径，不自行换算 |
| 分母口径 | 取消率的分子（当周取消）和分母（当周 GMV）不一定是同一批订单 | 引用工具给出的口径说明 |
| 左删失 | 靠近数据起点的周，部分老客会被算成新客 | 引用新客相关警告，新老客结论从严 |
| 小样本 | 订单只有几单的国家“归零”或“翻倍” | 不对样本不足的分组下结论 |
| 相关当因果 | 没有对照实验却写“导致”“因为” | 用“同时发生”“可能的原因（待验证）” |

## 4. 结论写法

每个驱动因素写一行，标明它属于哪一类：

- **数据事实**：工具直接给出的数字和结构，注明来自哪个工具。
- **推断**：由事实推出的判断，必须写出依据；没有依据就不写。
- **待验证假设**：业务原因（为什么会这样），必须注明“待业务确认”或“需要实验验证”。

避免：循环解释（“GMV 上升是因为销售额上升”）、笼统表述（“多种因素共同作用”）、只谈最大的一项而忽略抵消项。

## 5. 输出格式

1. **结论**：一两句话；不可比时第一句先说明。
2. **主要驱动**：按贡献大小排序（Shapley 值），每条带数字和出处。
3. **需要注意**：警告与陷阱清单中命中的项。
4. **建议下一步**：还需要看什么数据、向业务确认什么、是否需要实验。
5. **可信度自评**：可直接分享 / 说明局限后分享 / 需修改后再分享，并写一句理由。

## 6. 边界

- 所有数字来自工具返回的结果，不自己计算。
- 不下因果结论，不做预测。
