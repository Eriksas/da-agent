# 把查询 Agent 接进原来的 Agent：评分标准（M19b）

**冻结时间：2026-11-17，在留出题上第一次运行之前提交。** 之后发现的问题另行记录，不改这一版，也不改题目和参考 SQL。

## 要检验什么

M19 证明了：请求写得明确时，查询 Agent 能把数算对。M19b 把它作为一个工具（`query_data`）交给原来的 Agent：用户问的问题含糊，原来的 Agent 负责理解问题、写出明确的取数请求、解读结果、写回答；查询 Agent 负责写 SQL 算数。

量两件事：

1. **新能力**：固定工具答不了的问题，加上取数之后能不能答对。
2. **不变差**：固定工具本来就能答的问题，加上取数之后有没有变差（例如放着带警告的固定工具不用，什么都走 SQL）。

## 两个对比组

都用同一个模型（MiniMax-M3.1-Flash，2026-11-16 起的默认模型），同样的分析流程、同样的数字核查和退回修正：

- `agent_skill`：现在的做法，只有固定工具。
- `agent_query`：在它的基础上加 `query_data`。取数时查询 Agent 用同一个模型。

换了模型，所以两组都重新跑，不和以前在 Preview 上跑的成绩比。

## 题目

- **新题**（[query_e2e.yaml](query_e2e.yaml)，10 道）：固定工具答不了的问题，问法像真实用户，例如“2011 年下半年，客户一般几点下单最多？”。9 道要算数，1 道应该拒答（问毛利率，数据里没有成本）。两道带陷阱：最后一个季度不完整；被取消金额最多的商品是一笔当天下单、当天全部取消的极端大单。
  每道题的正确数值由参考 SQL 在评测数据上直接算出（不经过查询 Agent），每个数都要出现在答案里。
- **回归题**：原来的 10 道（[cases.yaml](cases.yaml)）和 5 道留出题（[holdout.yaml](holdout.yaml)），评分规则不变。
- **开发题**（[query_e2e_dev.yaml](query_e2e_dev.yaml)，3 道）：每组跑了 1 次（[e2e-dev-1](results/e2e-dev-1/summary.md)）：`agent_query` 3/3、`agent_skill` 0/3。取数说明和提示词没有因此改动。成绩不算数。

每道题每组跑 2 次：新题 40 次、回归题 60 次，共 100 次运行，只跑一次。

## 怎么算通过

和以前的评测一样由程序判定：正常结束；要点全部提到；没有违规说法；答案里的数字全部有出处；正确数值都出现在答案里（按答案自己的显示精度比较）。

取数结果里，查询 Agent 自己写的说明（`unverified_notes`）不当出处：答案引用了其中的数，算作没有出处。

模型接口报错（限流、超时）的运行等一会儿重跑，最多 4 次，重跑次数照实记录。

## 结论的标准（运行前定下）

| 结论 | 要求 |
|---|---|
| 新能力成立 | 新题上 `agent_query` 通过 ≥ 14/20，并且比 `agent_skill` 多通过 ≥ 6 次 |
| 不变差 | 回归题上 `agent_query` 的通过次数不少于 `agent_skill` 减 3（30 次运行里） |

两条都达到：`da-agent ask` 默认开启取数（`--no-query` 可以关掉）。周报不变，仍然只用固定工具。

有一条没达到：取数保留为 `--with-query` 选项，不默认开启，并在记录里写明差在哪里。

“减 3”的来历：M16 里同一个模型原样重跑财报题，16 题的通过数从 16 变成 13，同一套题重跑本来就会差几次。

另外照实记录（不设门槛）：回归题上有多少次运行用了取数、每次回答的平均 token（含查询 Agent）和用时。

## 打分本身可能出错

- 标题数字用程序的打分，原样报告。
- 新题上 `agent_query` 的每一次未通过，逐条看原因：是真的答错，还是题目或评分的问题（例如同一个意思换了说法、合理的另一种口径）。判断写进结果目录的 `adjudication.json`，在结论里另列一行“复核后”的数字，不替换程序的数字。
- 判断的是 Claude（代项目作者，作者本人未逐条核对）。

## 已知的局限（运行前写下）

- 新题只有 10 道，每道 2 次；题目、参考 SQL、取数说明是同一个 AI 写的。
- 新题的正确数值只有一种口径。例如“占全年 GMV 多少”按全部 GMV 算（含缺客户 ID 的订单）；按可识别客户算会判错。
- `agent_skill` 在新题上本来就几乎不可能通过：这一组的作用是确认题目确实是固定工具答不了的，不是为了显得新做法更好。
- 回归题是以前调提示词、流程时反复用过的，在它们上面不变差，不代表在别的问题上也不变差。
