# Agent 自主搭看板：Bank Marketing 盲测评分表（M13b）

**冻结时间：2026-10-14，在第一次用真实模型运行之前提交。** 之后发现的评分问题另行记录，不改这一版。

## 测试设置（盲测）

- 数据：UCI Bank Marketing（`bank-additional-full.csv`，41,188 行，21 列，CC BY 4.0），葡萄牙一家银行 2008-05 至 2010-11 的电话营销，每行是一位客户，y 表示是否订阅了定期存款。
- **Agent 拿到的只有 CSV**：没有语义标注、没有数据说明（`bank-additional-names.txt` 只用来写这份评分表），列的含义只能从列名和取值判断。
- 读者和目标：营销负责人复盘这轮电话营销——整体转化怎么样、哪些客群和渠道转化更高、需要注意的数据问题。
- 计划跑 2–3 次；每次单独记录，结论写明样本量。

## 我先探查到的事实（写评分标准用）

| 事实 | 数字 |
|---|---|
| 整体转化率 | 11.27%（4,640 / 41,188） |
| pdays = 999 表示“之前没联系过” | 96.32% 的行；直接平均 962.5 天，去掉 999 后 6.0 天 |
| unknown 是缺失值 | default 20.9%（选 yes 的只有 3 人）、education 4.2%、housing 和 loan 各 2.4% |
| 月份没有年份 | 数据跨 2008-05 至 2010-11，同一个月份混了三年；不是时间序列 |
| 小样本的极端转化率 | 12 月 48.9%（182 人）、3 月 50.5%（546 人）、学生 31.4%（875 人）、60 岁以上 39.6%（1,193 人） |
| 通话时长是通话之后才知道的 | 订阅的人平均 553 秒，没订阅的 221 秒；不能当成转化的原因 |
| 宏观经济指标 | emp.var.rate 等 5 列每个时期一个值，不是客户属性；求和或平均成 KPI 没有意义 |

## A. 能独立完成（全部满足才算“独立完成”）

同 [dashboard_rubric.md](dashboard_rubric.md) 的 A1–A4：正常结束并生成页面、没有超过工具上限（25 次）、先了解数据再设计、放进看板的图提交前都预览过。

## B. 口径

| 编号 | 检查 |
|---|---|
| B1 | 转化率 = 订阅人数（y = yes）÷ 联系的客户数 |
| B2 | 不把 pdays 的 999 当成天数：没有对 pdays 求和或求平均（不排除 999）的指标 |
| B3 | 宏观经济指标不做求和，也不当成整体 KPI |

## C. 选图

| 编号 | 检查 |
|---|---|
| C1 | kpi 2–4 张，图一共 6–9 张 |
| C2 | 至少一张按客群（职业、年龄、教育等）的转化率对比，至少一张按渠道或联系方式（contact、poutcome、campaign 等）的转化率对比 |
| C3 | 每张图的 why 写了它回答的业务问题 |

## D. 数据陷阱（盲测的重点：没人告诉它）

| 编号 | 陷阱 | 算发现了的标准 |
|---|---|---|
| D1 | pdays = 999 是特殊值 | notes 或 insight 写明 999 不是真实天数（例如“之前没联系过”），或者完全不用 pdays 而改用 previous / poutcome |
| D2 | unknown 是缺失值 | notes 写明 unknown 的含义或占比，尤其 default |
| D3 | 月份没有年份 | 不把月份当成时间趋势（不画成按时间顺序的折线），或在 notes 写明没有年份 / 可能跨年 |
| D4 | 小样本的极端转化率 | 对转化率特别高的小分组，写明样本量，或在 notes 提醒 |
| D5 | 通话时长事后才知道 | 如果用了 duration，没有把它写成转化的原因，并说明它是通话后才知道的；没用则不适用 |

## E. 结论

| 编号 | 检查 |
|---|---|
| E1 | insight 没有因果表述（报告核查同一份词表） |
| E2 | insight 的数字都有出处（程序强制；记录被退回的次数和原因） |
| E3 | 最后的回答里数字都有出处 |

## F. 记录但不评分

模型调用次数、token、用时、工具调用次数、被退回的次数和原因、程序本身的限制（例如月份只能按字母排序、where 只能列出允许的取值不能排除）、Agent 没做但人会做的事。
