# 数字归属核对：评分标准（M18）

**冻结时间：2026-11-15，在留出集上第一次运行之前提交。** 之后发现的问题另行记录，不改这一版。

## 要检验什么

数字核查只查“数字在工具结果里出现过”，查不出数字被安在了别的指标、别的分组上。M15 用第二个 Agent 去查这类错，结论是它查得出，但不够准、不稳定，而且每次要花约 5.7 万 token。

M18 换一个办法：工具结果是结构化的，每个数都带着名字（指标、分组、公司）。程序看答案里每个数前面最近的名字是不是它自己的，不调用模型（[attribution.py](../src/da_agent/attribution.py)）。这次量两件事：

1. 植入的“数字安错对象”，它能指出多少。
2. 没有改动的答案上，它会标出多少，其中多少是真的。

## 材料（[attribution_cases.yaml](attribution_cases.yaml)）

- **开发集**（23 份）：调规则时反复用过。结果是 11/16 的对象替换被指到、原样答案上 0 条“对象”标记。**这些成绩不算数**，规则就是看着它们改出来的。
- **留出集 A**（16 份）：复核 Agent 评测（M15）用过的答案。调规则时没有在它们上面跑过。
- **留出集 B**（最多 69 份）：多模型对比（M16）里三个模型新写的答案，每道题取带流程的第 1 次运行（正常结束、有答案的）。
- 植入错误沿用 M15 的两种方式，代码不改：对象替换、数字对调。给 A 的全部答案和 B 里 Flash 的答案植入；另外两个模型的答案只看会不会乱报。
- 有两处人工发现过的真实错误（把“占总变化的比重 -1.66%”当成降幅）在调规则时看过，属于开发材料，不计入留出集。

留出集只跑一次。跑完之后不再改规则；要改，得再找一批没用过的答案。

## 怎么算

**植入的错误**（程序判定）：改过的那一句里有一条“对象”标记，算“指到了”。原样答案的同一句本来就有“对象”标记的，记为“分不清”，不计入。

**原样答案上的标记**（人工判断，Claude 代项目作者判断，作者本人未逐条核对）：
- “对象”标记：回到工具结果看这个数属于谁。**成立** = 这句话确实把这个数说成了别的指标、分组或公司的；**不成立** = 这个数就是这句话说的那个对象的（程序认错了名字，或者读错了句子）；**有争议** = 取决于这句话怎么读。
- “含义”提示：**成立** = 这一行确实把“占总变化的比重”写成了一个没有说明的百分比；不要求答案因此得出了错误结论。

## 结论的标准（运行前定下）

| 用途 | 要求 |
|---|---|
| “对象”标记接入核查结果和报告（只标记，交给人看） | 留出集 A、B 合计：“对象”标记 ≥ 5 条时至少 80% 成立；少于 5 条时不成立的不超过 1 条。并且植入的“对象替换”检出率 ≥ 60% |
| “含义”提示接入报告 | 留出集上的提示至少 90% 成立 |
| 把标记自动退回给写答案的 Agent 修改 | 这一轮不做：需要先看标记在真实答案里有多少、对不对 |

“数字对调”的检出率只记录，不设要求：对调的两个数常常是同一个指标的两期数（名字相同），或者是没有名字的数，按设计查不出。

## 已知的局限（运行前写下）

- 只看数字前面同一分句、24 个字符以内的名字。名字在后面、在上一句、在表格的表头里，都不查。
- 一个数只要有一处出处没有名字（警告里的数、calculate 的结果），就不查。
- 本期和基期弄反、同一指标不同周的数弄混，不查：它们的名字相同。
- 国家的中英文对照是一张手写的表，只覆盖这份数据里出现的国家。
- 植入的错误是“把名字换掉”，正好是这个检查的强项；检出率是上限。
- 判断“成立 / 不成立”的和写规则的是同一个 AI。每条判断的依据都留在结果目录里。
