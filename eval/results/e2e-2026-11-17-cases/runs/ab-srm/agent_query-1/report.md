**问题：** 我们做了一个满减实验，按 50/50 分流：对照组 5000 人中 400 人下单，实验组 5600 人中 480 人下单。实验组赢了吗？

## 结论

**实验组没有“赢”。** 两组转化率差异在统计上不显著（实验组 8.5714% vs 对照组 8%，差值 +0.5714 个百分点，p = 0.2871，95% 置信区间 [-0.48pp, +1.62pp]）。**更关键的是：这次分流出现了严重的样本比例失衡（SRM），按规范应先排查分流与埋点，暂不解读实验效果。**

---

## 主要原因（数字来自 ab_proportion_test）

**1. 转化率差异本身不显著**

| 指标 | 数值 |
|---|---|
| 对照组转化率 | 0.08（400 / 5000） |
| 实验组转化率 | 0.085714（480 / 5600） |
| 绝对差 | +0.005714（+0.57pp） |
| 相对提升 | +7.1429% |
| z 值 | 1.0644 |
| p 值 | 0.287131 |
| 95% 置信区间（绝对差） | [-0.004788, 0.016217] |
| 是否显著 | 否 |

置信区间跨过 0，且下界为 -0.48pp，说明当前数据既不能证明实验组更好，也不能排除实验组更差（差 0.48pp 以内）。

**2. 样本比例与 50/50 设计严重不符（SRM）**

| 指标 | 数值 |
|---|---|
| 总样本 | 10600 |
| 实际对照组占比 | 0.471698（5000 人） |
| 实际实验组占比 | 0.528302（5600 人） |
| 期望对照组 / 实验组人数 | 各 5300 |
| 对照组偏差 | -300 人 |
| 实验组比对照组多 | 600 人 |
| 卡方统计量 | 33.9623 |
| SRM p 值 | 0.0 |

按 50/50 分流，随机误差不应该产生 600 人的系统性偏差（p = 0.0）。这通常指向分流逻辑、埋点丢失或去重（如同一人被重复分配进两组）等问题。

**3. 样本量本来也不足以检测这个量级的提升**

按基线转化率 0.08、要检测 0.0057 的绝对提升、alpha 0.05、power 0.8 计算（ab_sample_size）：每组需 36,712 人、合计 73,424 人。当前总样本 10,600 人，仅相当于所需样本量的约 1/6.93（73424 / 10600 = 6.926792）。

---

## 需要注意

- **不要用当前的 7.14% 相对提升去汇报“实验组赢了”**：一是 p = 0.2871 不显著，二是 SRM 已经让这个数字失去可信度。工具给出的明确建议是“样本比例与设计不符，先排查分流和埋点，暂不解读实验效果”。
- 这里的转化指标是“是否下单”。满减这类促销更常见的直接影响是**客单价/件单价**而非转化率；仅看下单率可能会低估或误判效果。
- 两组样本量不同（5000 vs 5600）本身不影响转化率对比（比例型指标），但和 SRM 一起出现时应视为分流异常而非设计如此。

---

## 建议下一步

1. **先修分流，再谈效果**：排查分流 hash 是否稳定、是否有用户重复入组或埋点重复上报；SRM 修复前不要下任何效果结论。
2. **补齐样本量**：按当前设计（50/50、基线 8%）跑满约 73,424 人（每组 36,712）再判读；若业务上接受不了这个量级，就改用更大的 MDE 或提高实验组流量。
3. **补一个金额类指标**：同时看实验组 vs 对照组的客单价、件单价、GMV/曝光，否则可能漏掉满减的真实收益点。
4. 若修复分流后仍想验证 0.57pp 这个量级，务必按上面第 2 条的样本量要求执行，避免再次得到“不显著但看起来有提升”的结论。
