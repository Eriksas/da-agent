# 满减实验结果分析

**结论：效果在统计上显著，但幅度很接近显著性边界，建议加时实验后再全量。**

## 检验结果

| 项目 | 结果 |
|---|---|
| 对照组转化率 | 400 / 5000 = **8.0%** |
| 实验组转化率 | 460 / 5000 = **9.2%** |
| 绝对差值 | **+1.2 个百分点**（0.012，calculate 计算） |
| 相对提升 | **+15%**（relative_lift） |
| z 值 | 2.1401 |
| p 值 | **0.032349**（< α = 0.05，判定显著） |
| 差值 95% 置信区间 | [0.001012, 0.022988]，即 **+0.10 ~ +2.30 个百分点** |

以上均来自 `ab_proportion_test`（两比例 z 检验，检验用合并比例、置信区间用非合并标准误）。

**样本比例失衡检查（SRM）：** 卡方拟合优度检验 chi2 = 0.0、p = 1.0，实际分流 0.5 / 0.5 与设计的 0.5 完全一致，`sample_ratio_mismatch = false`，分流无异常。

## 需要注意

1. **显著性是"擦线"过的**：置信区间下限仅 0.001012（下限贴近 0），意味着本次结果的把握度不高，换一批流量可能就测不出差异；同时它也是一个"显著但区间很宽"的结论——真实效果可能落在 +0.10 到 +2.30 个百分点之间，方向可靠但幅度不确定。
2. **统计显著 ≠ 业务划算**：满减有直接成本，本次实验只提供了下单转化率，未提供客单价、订单毛利率、补贴核销等数据。按 15% 的相对提升如果伴随客单价下降或毛利侵蚀，净收益可能为负。工具未提供这些数据。
3. **口径与样本**：每组 5000 人属于中等样本，未触发工具 warnings（`warnings: []`）；实验未说明是否只跑了一个流量池、是否有其他同期实验或促销叠加，这些都可能干扰归因。
4. 本次检验为观测性对比而非因果推断的绝对保证——虽然做了随机分流的 SRM 检查，但用户未提供随机化细节（如分流单位是用户还是会话、是否存在同用户跨组）。

## 建议下一步

1. **先算清 ROI 再推全量**：补充实验组/对照组的客单价、毛利、补贴金额，算出每单净利润变化；只看下单率容易被"低客单换来的转化"误导。
2. **加时实验提高把握度**：按 `ab_sample_size`（基线 8%、想检测 +1.2 个百分点、α=0.05、power=0.8）计算，每组需 **8568** 人、总计 **17136** 人，当前每组 5000 人尚未达到该样本量。继续跑到每组约 8568 人，结论会更稳。
3. **若业务上更看重"最小有意义提升"**，可用更大的 MDE（例如 +2 个百分点）反推所需样本，再决定是否值得继续投入。
4. **分群看效果**：检查新老客、不同国家/地区的转化差异是否一致，避免提升全部来自某一小流量段（可用 `drilldown` 按 customer_type、country 拆分核对）。
5. **多实验并行时做多重比较校正**（如 Bonferroni），避免多个满减档位同时实验时的假阳性。
