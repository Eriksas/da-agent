**问题：** 我们做了一个满减实验，按 50/50 分流：对照组 5000 人中 400 人下单，实验组 5600 人中 480 人下单。实验组赢了吗？

# 结论：没有赢，而且这个实验目前**不能解读**

两个层面的问题：统计上实验组并不显著（p = 0.2871），更关键的是**样本比例失衡（SRM）检验不通过**，工具给出的建议是"先排查分流和埋点，暂不解读实验效果"。

---

## 主要原因（按严重程度）

**1. 样本比例与 50/50 设计严重不符 —— 硬伤，先修这个**（来自 `ab_proportion_test` 的 SRM 检验）

| 项 | 数值 |
|---|---|
| 设计对照组流量占比 | 0.5（期望各 5300 人） |
| 实际对照组占比 | 0.471698（5000 人） |
| 实际实验组占比 | 0.528302（5600 人） |
| 对照组与期望偏差 | -300 人（实验组比对照组多 600 人） |
| 卡方统计量 | 33.9623 |
| p 值 | 0.0 |

p = 0.0 意味着这种偏离不可能是随机波动造成的。方向性也很明确：**实验组比对照组多进了 600 人**。这种"实验组偏多"通常对应分流脚本/桶位哈希不均、某一路由或实验位只对部分流量生效、或实验组埋点重复计数等具体故障。在流量分配本身就不可信的前提下，组间转化率差异不能归因于满减策略。

**2. 即使抛开 SRM，效果也不显著**（来自 `ab_proportion_test` 的两比例 z 检验）

- 对照组转化率：0.08（400 / 5000）
- 实验组转化率：0.085714（480 / 5600）
- 绝对差：+0.005714（+0.5714 个百分点）；相对提升 0.071429（+7.14%）
- z = 1.0644，p = 0.287131，**significant = false**
- 95% 置信区间：-0.004788 ~ +0.016217（即 -0.4788 ~ +1.6217 个百分点）

置信区间跨过 0，说明在当前样本量下无法拒绝"满减无效果"这一假设；观察到的 +7.14% 相对提升完全落在随机波动范围内，不能作为"实验组赢"的证据。

**3. 样本量本身也不够**（来自 `ab_sample_size`）

若目标是检测基线 8% 提升到 8.5714%（绝对 +0.5714pp），在 alpha = 0.05、power = 0.8 下需要**每组 36536 人、合计 73072 人**；当前每组仅 5000 / 5600 人，实验组还需补充 30936 人。样本不足是 p 值偏大的直接原因之一。

## 需要注意

- 以上转化率与 p 值、置信区间均由你提供的 400/5000 与 480/5600 计算得出，工具未做其他口径调整。
- 相对提升 7.14% 是**观测值**，不是效应估计的可靠估计；在 SRM 未修复前它可能纯粹来自分流不均（例如高活跃用户被更多分到实验组），请不要拿它做决策。
- 建议不要重复跑同一个实验来"求一个显著结果"，而是先定位分流问题。

## 建议下一步

1. **查分流与埋点（优先级最高）**：核对分流哈希/桶位配置是否真正 50/50、实验组多出的 600 人来自哪个入口或时间窗、是否有个别用户被重复计入或跨组；用 UV/设备 ID 维度比对两组的去重人数与曝光量，看 SRM 是出在"分配"环节还是"埋点"环节。
2. **修复后重跑**，并确保两组曝光人数口径一致（都只统计真正命中实验的用户）。
3. **按真实业务目标定 MDE 再算样本量**：如果业务上认为 +0.5pp 的提升不足以覆盖满减成本，应把 MDE 设在有意义的幅度（例如 ≥1pp），再据此评估所需流量是否可承受——用 `ab_sample_size` 以你的目标基线与 MDE 重算，并与流量供给对比。
4. **同步看 GMV/客单价而不只看转化率**：满减常出现"转化率微涨但客单价下滑、净 GMV 不增"的情况，本仓库有 `metric_summary`、`decompose_gmv`、`drilldown` 可按周拆解；不过要注意这些是周度运营数据（2011-W48 等），与本次实验的日级口径不同，需要单独对齐。
