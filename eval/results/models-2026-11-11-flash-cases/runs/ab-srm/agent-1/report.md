# 满减实验结论：目前**不能判定实验组赢**，而且这次数据本身就有分流异常，建议先排查再解读效果

## 1. 结论

- **效果上没有赢**：对照组转化率 8.0%，实验组 8.5714%，绝对差 +0.5714%，相对提升 7.1429%，但 **p = 0.287131，不显著**，95% 置信区间为 [-0.4788%, +1.6217%]（跨过 0）。也就是说，真实效果可能是负的，也可能是正的，现有样本无法区分。
- **更关键的问题：分流比例失衡（SRM）**。按 50/50 设计，10600 人应各分到 5300，实际对照组 5000 人、实验组 5600 人，**实验组比对照组多 600 人**，卡方拟合优度检验 chi2 = 33.9623，p = 0.0，样本比例与设计不符。

## 2. 主要原因（按重要性）

| 项目 | 数值 | 来源 |
|---|---|---|
| 对照组转化率 | 0.08（400/5000） | ab_proportion_test |
| 实验组转化率 | 0.085714（480/5600） | ab_proportion_test |
| 绝对差 / 相对提升 | 0.005714 / 0.071429 | ab_proportion_test |
| z 值 / p 值 | 1.0644 / 0.287131（不显著） | ab_proportion_test |
| 95% 置信区间 | [-0.004788, 0.016217] | ab_proportion_test |
| 实际对照组占比 vs 设计 | 0.471698 vs 0.5 | ab_proportion_test（SRM） |
| 期望对照/实验人数 | 5300 / 5300，实测 5000 / 5600 | ab_proportion_test（SRM） |
| SRM 卡方与 p 值 | chi2 = 33.9623，p = 0.0 | ab_proportion_test（SRM） |

- **差异不显著是样本量不够，不是"没效果"**：按 8% 基线、检测 0.5714 个百分点提升，alpha=0.05、power=0.8 需要**每组 36536 人、总计 73072 人**（ab_sample_size）；当前每组仅 5000/5600 人，差距巨大。
- **SRM 是"效果不可信"的独立问题**：分流明显偏向实验组（多 600 人），工具给出的处理建议是"先排查分流和埋点，暂不解读实验效果"。在分流/埋点未查清前，即便 p 值显著也不能采信。

## 3. 需要注意（数据口径与警告）

- ab_proportion_test 返回的 warnings 为空，但 **SRM 判定为 true**，该警告必须优先处理；此外本次是单次下单口径的转化率，未考虑人均订单/GMV，实验是否影响客单价需另看。
- 未做多重检验校正（本次只有 1 个指标、1 个对比，无此问题）。
- 样本比例失衡常见原因：分流哈希/分桶不均、机器人与爬虫流量被导向实验组、埋点丢失或去重规则对两组不一致、实验开启期间新老用户进入比例变化。这些都未在本工具覆盖范围内，需人工核查。

## 4. 建议下一步

1. **先做 SRM 排查**：核对分流日志与实际曝光/入组口径，比对两组的流量来源渠道、机型、新老客占比、地理分布是否一致；重点查实验组多出的 600 人是"被多分到的真实用户"还是"重复入组/未去重的日志"。
2. **修复后再复跑**：若确认是埋点或去重问题，清洗数据后重新检验；若确属随机分流偶发，需确认各随机种子下的分桶偏差是否可接受。
3. **补足样本量**：若确实想验证 8% → 8.5714% 这个量级的提升，每组需扩到约 36536 人；若业务上只关心 1 个百分点以上的提升（8% → 9%），每组约需 12208 人、总计 24416 人（ab_sample_size），可据此定扩量目标。
4. **补充护栏指标**：满减通常压毛利，赢下转化率不等于赚。建议同时看 GMV/客单价、客单毛利、优惠成本，把"下单率提升"与"单位用户利润"一起作为决策依据。
