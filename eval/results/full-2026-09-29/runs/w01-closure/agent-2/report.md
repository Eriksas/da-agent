**问题：** 2011-W01 的 GMV 环比变化怎么看？

## 结论

**2011-W01 的环比口径不可用。** 基期 2010-W52 整周停业（0 个交易天，GMV 记为 0），所以工具返回的"GMV 环比 +130,274.65"只是从 0 起算，变化百分比是 `null`——这是停业造成的统计假象，不是真实增长（`metric_summary` warning：「基期 2010-W52 整周没有交易（停业），各项指标为 0」）。

换一个可比基期（同比 2010-W01）看，**2011-W01 GMV 为 130,274.65，去年同期 166,010.79，减少 35,736.14，降幅 21.53%**。这一下降几乎全部来自客单价走低，而客户数其实是增长的。

## 主要原因（同比口径，工具：`metric_summary` / `decompose_gmv` / `drilldown`）

**1）可识别客户客单价大幅下滑 —— 唯一的量级大负项**

- Shapley 贡献 **-77,797.41**，占总变化 **217.7%**
- 整体客单价口径同样：830.05 → 538.33，-35.15%（`metric_summary` aov）

**2）活跃客户数增长，部分对冲了客单价的下滑**

- 缺客户 ID 的 GMV：591.63 → 16,801.60，Shapley 贡献 **+16,209.97**
- 人均订单数 1.1265 → 1.0821，Shapley 贡献 **-5,700.00**（小项）
- 四项合计正好 -35,736.14，`check.contributions_sum_to_total = true`

## 需要注意

- **环比无解**：跨年停业 2010-12-23 → 2011-01-04（gap 12 天），2010-W52 完全无交易。`data_quality_overview` 把 2010-W52 列入 `low_trading_weeks`（trading_days = 0），并把 2009-W53 同样标为 0 交易天。任何"跨年环比"都要手工绕开。
- **同比基期有系统性偏差**：`metric_summary` 明确警告「基期 2010-W01 距数据起点不足 52 周：起点之前的购买看不到，部分老客会被算成新客」。数据起点是 2009-12-01，2010-W01 几乎紧贴起点，去年那 67 个"新客"很可能大部分是真实老客。因此"新客 GMV -82.28%"这个数字**很可能被夸大了，不宜直接当作拉新失灵的证据**。
- **交易天数不同**：本周 5 天 vs 去年 6 天（少 1 天），未做日均化，所以 21.53% 的降幅里含有一天营业日的差异。
- **取消率上升**：0.0078 → 0.0366，变化 +0.0288（约 2.88 个百分点）。口径提醒：分子分母不一定是同一批订单。
- **样本量不足警告**：新老客拆解中新客（基期 68 单/本周 14 单）和未知分组均被标记为小样本。
- 以上都是同期对照下的结构描述，属于"与……同时发生"，不能推断因果——没有做任何对照实验。

## 建议下一步

1. **放弃 2011-W01 的环比，改用 2010-W51 作为节前参照**：2010-W51 GMV 85,203.04（4 个交易天），比 2010-W50 的 208,616.61 低 59.16%——圣诞周本身就在收缩。所以 2011-W01 的 130,274.65 相对节前水位其实是回升的，"同比降 21.53%"和"节前相比在恢复"两个结论并不矛盾，业务上以后者为准。
2. **重点查客单价为什么掉**：拉 2011-W01 的订单件数分布，看是件数变少还是高价单品断档；对比 2010-W01 是否有大额团购/批量单集中在少数几单。
3. **用 2010-W53 之后的有数据周做新客基线**，避开数据起点不足 52 周的偏差，再判断拉新是否真的下滑。
4. **查缺客户 ID 的 GMV 异常**：本周 16,801.60、占 GMV 比例明显高于去年同期的 591.63，且集中在"未知"分组（18 单）。这可能意味着下单流程或数据导出出了问题——占总量 13.11% 的订单没有客户 ID（`data_quality_overview` clean_totals），值得核一下上游采集。
5. 如果要确认客单价策略的影响，建议设计一次 A/B（如默认加购/组合推荐），用 `ab_sample_size` 算好样本量再跑，不要靠前后对比下结论。
