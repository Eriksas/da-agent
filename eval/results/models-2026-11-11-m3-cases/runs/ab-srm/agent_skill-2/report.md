**问题：** 我们做了一个满减实验，按 50/50 分流：对照组 5000 人中 400 人下单，实验组 5600 人中 480 人下单。实验组赢了吗？

## 结论

**没有赢。** 从你给的数据看，实验组转化率 8.5714%（480/5600）高于对照组 8%（400/5000），绝对差 +0.5714pp、相对提升 7.14%，但：

1. **统计上不显著**：z = 1.0644，p = 0.287131，95% 置信区间 [-0.4788pp, +1.6217pp]，区间跨 0，不能判定实验组更优；
2. **而且分流样本比例失衡（SRM）**：对照组实际占 47.1698%（期望 50%，卡方 33.9623，p = 0.0），按检验工具的建议，"先排查分流和埋点，暂不解读实验效果"——所以连上面那个"不显著"的差异本身也不可信。

## 主要原因

| 检验项 | 结果（来自 `ab_proportion_test`） |
|---|---|
| 对照组转化率 | 0.08（400/5000） |
| 实验组转化率 | 0.085714（480/5600） |
| 绝对差 | 0.005714 |
| 相对提升 | 0.071429 |
| z 值 / p 值 | 1.0644 / 0.287131 |
| 95% 置信区间 | [-0.004788, 0.016217] |
| 是否显著 | false |
| SRM：实际对照组占比 | 0.471698（期望 0.5，少 300 人） |
| SRM 卡方 / p 值 | 33.9623 / 0.0，`sample_ratio_mismatch = true` |

**样本量也不足以支撑这个量级的结论**（来自 `ab_sample_size`）：

- 要在 80% 把握度下检测到本次观察到的 0.57pp 提升，每组需 **36,712** 人（合计 73,424），而实际只有 5,000 / 5,600 人；
- 若业务上认为"至少要 2pp 的提升才算值得做"，每组需 3,213 人（合计 6,426），当前样本量在这个量级上是够的——但前提是先修好分流问题。

## 需要注意

- **SRM 是硬伤**：50/50 分流下对照组比期望人数少 300 人（期望 5300 人，实际 5000 人，偏差 -5.66%，由 `calculate` 计算），远超随机波动范围。常见原因：分流哈希/埋点丢失、机器人与内部流量未排除、跨设备重复计数、或实验期间有流量被误分到实验组。**在 SRM 未解释清楚前，这批数据不建议用于任何决策**（包括"满减没效果"的结论）。
- 转化率的差异（8% → 8.5714%）同时可能来自**样本构成差异**（两组的用户质量/新老客结构是否一致，工具未提供）与**真实的满减效果**，本次数据无法区分。
- 工具口径：两比例 z 检验，检验用合并比例、置信区间用非合并标准误，α = 0.05；`ab_proportion_test` 未返回额外 warnings。
- 这里只做了转化率（二项）检验，未涉及 GMV/客单价等金额指标；满减通常还会带来客单价下降，转化率升不等于整体 GMV 升。

## 建议下一步

1. **先查分流**：核对分流日志与埋点，确认 50/50 的实际分流比例、是否有曝光/掉线导致的用户丢失、是否存在跨设备重复计数；排除内部与机器人流量后重跑 SRM 检查。
2. **重新取数后复测**：分流修复后重跑转化率检验；若差异方向一致但仍不显著，说明效果幅度小于当前样本量能识别的下限。
3. **明确业务最小可检测效应（MDE）**：和业务方确认满减值不值得的提升阈值（例如 2pp），再据此决定是延长实验（当前样本对 2pp 量级够用）还是直接判负。
4. **补充金额侧指标**：把 GMV、客单价、每用户毛利纳入实验指标一并看，避免只看转化率做决策。
