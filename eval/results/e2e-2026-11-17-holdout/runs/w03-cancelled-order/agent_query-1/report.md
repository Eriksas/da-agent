# 2011-W03 GMV 环比诊断

## 1. 结论

**不是卖得更好，是一笔异常大额订单把 GMV 撑起来的。** 2011-W03 GMV 环比 +11.77%（187,291.30 → 209,331.26），但其中包含发票 **541431** 这一笔 **77,183.60 英镑**的极端大额订单（占当周 GMV 的 **36.87%**，来自 `metric_summary` 警告与 `calculate`）；该订单在下单后 **16 分钟**即被取消（销售单 2011-01-18 10:01，取消单 C541433 10:17，来自 `query_data` 明细）。

剔除这笔订单后：GMV **132,147.66**（`calculate`：209,331.26 − 77,183.60），环比 **-29.44%**（`calculate`）；净销售额 **130,490.66**，环比 **-29.44%**（`metric_summary`）；订单数 **229**（-11.24%）；活跃客户 **185**（-12.74%）。**业务实际是明显下滑，"涨一成"是统计假象。**

**按新老客（`drilldown`）**

**参照口径**：2011-W02 本身是强周（对 W01 GMV +43.77%，但因 W01 只有 5 个交易日，日均仅 +19.81%）；与 2010-W03 同比看，净销售额 130,490.66 也是 **-8.92%**（`metric_summary` yoy），说明 W03 的实际水平低于去年同期，不存在"年初开局变好"。

## 4. 需要注意（口径与警告）

1. **取消率 37.66% vs 上周 1.25%** 是同一笔异常单造成的（当周取消金额含 77,183.60），不是真实的退款恶化；取消金额按取消发生时间入账，分子分母不一定是同一批订单。
2. **GMV 是下单口径**，含之后被取消的订单；净销售额已扣除该单，所以两个指标方向相反本身就是异常单的特征。
3. 异常单数量 74,215 件、单价 1.04（`query_data`），与"STORAGE JAR"这一商品常识不符，**更像是录入/数据错误而非真实大单**（待业务确认）。数据质量清单中同类极端大额行共 38 条、列入人工复核（`data_quality_overview`）。
4. **同比基期左删失**：2010-W03 距数据起点不足 52 周，部分老客会被算成新客，新客同比 -87.16% 不可全信。
5. 交易天数两周均为 6 天，本次对比不存在交易日差异问题。
6. `query_data` 第一次请求因执行次数上限被拒（`status: declined`），其备注中的数字未采信；上述订单明细来自第二次成功查询返回的 rows。

## 5. 建议下一步

1. **修数据**：把发票 541431 / C541433 送人工复核，确认是录入错误（数量 74,215 件）还是真实订单；在周报口径中固定剔除"24 小时内被等量取消的极端大额行"后再看趋势。
2. **改看板口径**：建议以净销售额、日均 GMV、订单数作为主指标，GMV 需带"含未取消大额单"的标注，避免这类假涨。
3. **查真实下滑原因**：订单数 -11.24%、活跃客户 -12.74% 是真问题，需要拉 W03 分日数据看是集中在某几天（如是否受物流中断或春节前断档影响），并核对英国站 1 月中下旬的流量/转化与仓储履约情况。
4. **验证假设**：关于"为什么英国订单与客户同时下滑"的业务原因（缺货、促销节奏、站点故障等）需要向业务/技术确认，或用 A/B 或分日数据验证；本数据仅能说明两者同时发生，不能断定因果。

## 6. 可信度自评

**说明局限后分享**。核心结论（GMV 增长为单笔异常订单造成的假象、实际环比 -29.44%）有发票级明细与多口径交叉验证，可信；但对"真实下滑的业务原因"以及新客、国家等小样本分组，只能给方向性判断，尚不能作为定论。
