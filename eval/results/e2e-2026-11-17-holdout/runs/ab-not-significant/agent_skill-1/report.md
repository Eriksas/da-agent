# AB 实验结论：新版详情页「还不能说更好」

**分析对象**：本次 50/50 分流的商品详情页实验（对照组 8000 人 / 480 人下单，实验组 8000 人 / 520 人下单）。

## 1. 结论

实验组转化率看起来更高（6.5% vs 6.0%，相对提升 8.33%），但**统计上不显著**（z = 1.3064，p = 0.191418，significant = false），95% 置信区间为 [-0.2501, +1.2501] 个百分点，跨过 0。**当前证据不足以认定新版本更好**，也不足以说它更差。

## 3. 需要注意（口径与局限）

- **区间太宽，结果“方向性”强但精度差**：置信区间同时允许「下降 0.25 个百分点」和「上升 1.25 个百分点」两种解释，也就是说真实效果可能比观察到的差更小甚至为负。
- **指标口径**：本次转化定义为「下单」，若其中包含后续被取消的订单，会高估真实成交转化；建议在结论落地前用「支付成功/净销售额」口径复核一次。
- **只测了一个指标**：未做多重比较校正；若同时看了点击率、停留时长、加购等多个指标，需要相应调整显著性阈值。
- 工具返回 `warnings: []`，未提示样本或分流异常。

## 4. 建议下一步

1. **继续跑量，不要提前定胜负**：当前每组 8000 人。要在 6% 基线下检出「1 个百分点」的绝对提升（6% → 7%），每组需 9540 人（合计 19080），即当前样本量的 **1.1925 倍**（`calculate`）；若想检出实际观察到的「0.5 个百分点」提升，每组需 36791 人（合计 73582），约为当前的 **4.598875 倍**（`calculate`）。两数均来自 `ab_sample_size`（alpha=0.05，power=0.8）。
2. **先定好可接受的最小有意义提升（MDE）再决定跑多久**：若业务上认为「至少 +1 个百分点」才值得全量，那就以 9540 人/组为停止线；若要验证 +0.5 个百分点，则需把实验延长到约 3.7 万人/组。
3. **补齐护栏指标**：同时监控 GMV/客单价（防止转化提升但客单价下滑）、取消率与退款率，以及新客/老客分组效果，避免只优化了下单率。
4. **上线决策规则**：建议预先约定「只有当 p < 0.05 且置信区间下界 > 0 时才全量」，当前结果不满足，不建议现在做全量切换。
