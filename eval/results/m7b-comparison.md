# M7b 准确率提升：改进前后对比

> 2026-10-07，模型 MiniMax-M3.1-Flash-Preview，Agent 两组（不带流程、带流程）每题 2 次。下面的表格由 `da-agent eval-compare` 从各次评测的 `summary.json` 生成，每次运行的完整记录在对应目录的 `runs/` 下。

## 改了什么

1. **`calculate` 计算工具**（[calculator.py](../../src/da_agent/calculator.py)）：只做四则运算，先解析语法树再逐个检查，不用 `eval`。核查器同时检查算式的输入：输入找不到出处，算出的结果也不算出处。
2. **核查后退回修正**（[agent.py](../../src/da_agent/agent.py)）：答案里有找不到出处的数字时，程序把这些数字连同所在句子退回模型，修正一次（最多再调用 3 次工具）；修正失败时保留初稿。
3. **日均指标和“交易天数不同”警告**（[metrics.py](../../src/da_agent/metrics.py)）：以前少于 4 天才提醒，5 天对 6 天的银行假日周没有任何提示。
4. **小修**：AB 工具写明输入和推导量（如 SRM 的期望人数）；核查器忽略“### 2.1”这类小节编号；周报里 AI 部分的标题降两级。

## 怎么比

- **原题**（10 道，[cases.yaml](../cases.yaml)）：改进前是 M6 正式评测 [full-2026-09-29](full-2026-09-29/summary.md)，改进后是 [m7b-after-2026-10-07](m7b-after-2026-10-07/summary.md)。这些题用来找问题、定改进方向，提升里有一部分是“对症修出来的”。
- **留出题**（5 道，[holdout.yaml](../holdout.yaml)）：在改代码之前写好并单独提交，先用改进前的代码跑一遍（[holdout-before](holdout-before-2026-10-07/summary.md)），改完代码再跑（[holdout-after](holdout-after-2026-10-07/summary.md)）。
- **评分规则相同**：两次运行都跑完后发现两处评分缺陷（“4/21–4/25”里的 25 被当成数字；用“置信区间跨过 0”“significant = false”说明不显著没有被认出），修正后对改进前、改进后同时重评，重评前的结果表保留为各目录的 `summary.original.md`。M6 的结果也在副本上按新规则重评过：通过数不变，所以表里直接使用 M6 原结果。

## 怎么解读

1. **自动评分大幅提升，主要来自“核查后退回修正”**。只看初稿，原题是 10/20、12/20，留出题是 4/10、5/10，和改进前差不多；修正后才到 18/20、20/20、10/10、8/10。修正用的就是评分用的核查器，所以“数字全部有出处”这一项的提升有一部分是构造出来的：它说明系统交出的数字可以追溯，不说明推理变好了。
2. **不靠构造的改进**：
   - **W49**（不完整周 + 当天被取消的大单）：M6 四次运行全部得出错误结论。这次四次都用 `calculate` 算出剔除发票 581483 后 GMV 为 315,255.53、环比 +1.90%，与 M6 人工复核的结论一致；其中三次没有触发任何禁止说法。
   - **留出题里的三道陷阱**（被取消的大单、银行假日、小样本）：改进后两组都是 2/2。银行假日周抽查的两次答案都按日均给出 −13.41%（26,577.30 → 23,013.00）。
   - **被退回的 60 个数字**：18 个原样保留并补上了出处，22 个改成了相近的数（多为换成工具原数或用 `calculate` 重算），20 个被删掉。核查器抓到的不只是“算对了但没出处”的数，也有真错误：改进前的一次运行把占比 −11.4187（即 −1,141.87%，因为总变化只有 +1,446.39）写成了“−11.42%”。
   - **`calculate` 的输入检查**：改进后共调用 222 次，其中 4 次的输入找不到出处，结果没有被当作出处。例如模型先心算“英国 GMV 减去大单”，再把心算结果作为输入交给 `calculate`。
3. **代价**：每次运行的 token 约为原来的 1.9 倍（原题：16,165 → 30,286、20,884 → 38,729），模型调用次数也增加了；用时变化不大。
4. **带不带流程**：改进后两组在原题上是 18/20 和 20/20，在留出题上是 10/10 和 8/10。每题只跑 2 次，这样的差距在正常波动范围内，仍然不能说流程提升了准确率。

## 剩下的问题

1. W49 还有 1 次直接用不完整周的总量（订单数 −23.23%）得出“业务量下滑”。
2. W48 有 1 次因为“完全靠活跃客户数和人均订单数”触发禁止说法“全靠”。这句同时写了反向变化的客单价，是否算错需要人工判断。
3. 留出题“带流程”组的 2 次失败原因相同：模型在第一轮把工具调用写成了一段带标记的文字（`<tool_call>`、`<invoke` 等），程序把它当成了最终答案。评测后已加防护：识别后提示模型重发一次，再错就以 `malformed_answer` 结束，不把乱码当答案发布。没有重跑，表里的数字是加防护之前的。
4. 退回修正时有 20 个数字被删掉而不是补上出处：答案更“干净”，但信息可能变少。

## 局限

- 每题每组只跑 2 次，共 15 道题、单一模型；关键词评分是近似的。
- 留出题由 Claude 起草，没有由项目作者另外出题；两处评分修正是在看过答案之后做的（已记录，并对改进前后同时重评）。
- W49、W03、W22 的结论抽查由 Claude 辅助完成，待项目作者确认。

## 附录：统计脚本

“被退回的 60 个数字”和“`calculate` 的输入检查”两段的数字由下面的脚本算出，在仓库根目录用 `uv run python` 运行：

```python
"""M7b 附录统计：被退回修正的数字后来怎样了；calculate 用了多少次、多少次输入找不到出处。在仓库根目录运行。"""

import json
from pathlib import Path

from da_agent.checks import extract_numbers

RESULTS = Path("eval/results")
runs = [path for name in ("m7b-after-2026-10-07", "holdout-after-2026-10-07")
        for path in sorted((RESULTS / name / "runs").glob("*/*/run.json"))]
kept = rewritten = removed = calculations = unsupported = 0
for path in runs:
    run = json.loads(path.read_text(encoding="utf-8"))
    checks = json.loads((path.parent / "checks.json").read_text(encoding="utf-8"))
    calculations += sum(step["tool"] == "calculate" for step in run["steps"])
    unsupported += len(checks["numbers"]["unsupported_calculations"])
    if not run.get("repair"):
        continue
    final = extract_numbers(run["answer"])[0]
    for item in run["repair"]["ungrounded"]:
        if item["text"] in {m.text for m in final}:
            kept += 1  # 原样保留，修正后有了出处（修正后的答案数字全部有出处）
            continue
        value = extract_numbers(item["text"])[0][0]
        if any(abs(m.value - value.value) <= max(0.02 * value.value, value.tolerance) for m in final):
            rewritten += 1  # 改成了相差 2% 以内的数：多为换成工具原数，或用 calculate 重算
        else:
            removed += 1
print(f"改进后共运行 {len(runs)} 次；calculate {calculations} 次，其中输入找不到出处 {unsupported} 次")
print(f"被退回的数字 {kept + rewritten + removed} 个：原样保留并有了出处 {kept}，改成相近的数 {rewritten}，删掉 {removed}")
```
