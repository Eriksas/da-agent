# 查询 Agent：评测结果和结论（M19）

> 评分标准 [query_rubric.md](../query_rubric.md) 和题目在留出题运行前提交（ef6a464，2026-11-16 10:42:39；运行结束于 10:56）。打分由程序完成；没算对的运行由 Claude 代项目作者逐条复核（作者本人未逐条核对）。模型：MiniMax-M3.1-Flash-Preview。

## 结论

**查询 Agent 在留出题上达到了事先定的标准，可以作为工具接进原来的 Agent。但题目偏容易，这个成绩说明的是“明确的请求它能算对”，不是“什么问题它都能算对”。**

| 运行前定的标准 | 结果 | 达到了吗 |
|---|---|---|
| `retail` 配置 48 次运行：算对 ≥ 90%，“交了但不对”不超过 2 次 | 48/48，0 次 | 达到 |
| CSV 的 24 次运行：算对 ≥ 80%，“交了但不对”不超过 2 次 | 23/24，1 次 | 达到 |
| 口径配置有用：`retail` 比 `retail_raw` 高 10 个百分点以上 | 48/48 对 48/48 | **没有测出差别** |

## 为什么要做这个

原来的 Agent 只能调用写好的几个工具：工具没覆盖的问题（按星期几、按小时、复购）答不了，换一份数据要改代码。查询 Agent 把分析请求写成 SQL，程序执行后交出一张结果表。

让模型写 SQL 有两个风险，对应两层做法：

- **它可能写出危险的语句。** 数据库文件只读打开、关闭外部访问并锁住配置、只收一条 SELECT、有超时和行数上限（[sqlrun.py](../../src/da_agent/sqlrun.py)）。不经过字符串检查、直接把 15 种写入和读文件的语句交给连接，引擎全部拒绝（[test_sqlrun.py](../../tests/test_sqlrun.py)）。
- **它可能交出一个看起来没问题、其实算错了的数。** 这要靠评测来量，也是这份记录的主要内容。

交出去的结果是程序最后一次执行得到的表，不是模型抄写的数字。空结果、超过 200 行、列没有说明含义的提交会被退回。

## 题目和做法

- 留出题 36 道，写完后没有用模型跑过：固定工具也能答的 12 道、固定工具答不了的 10 道、没有任何配置的 CSV 11 道、应该拒答的 3 道。
- 每道题一条人写的参考 SQL。电商题的参考 SQL 在清洗后的基础表上执行，不经过查询 Agent 用的那张表；其中 12 道另有测试和固定工具核对一致。
- 电商的 24 道题在两份配置上各跑一遍：`retail` 把口径做成了现成的列（`gmv_amount`、`order_id`）和表达式；`retail_raw` 是同一份数据，口径只写成文字。
- 每道题每份数据跑 2 次，共 120 次运行，只跑了一次。
- 开发题 10 道跑了一次是 20/20，提示词没有改过；成绩不算数。

**唯一没算对的一次**（复核后仍然算错）：请求要“各访客类型成交订单的平均订单金额”，数据里没有金额列。它用 PageValues（页面价值）当代理，交了一张结果表。它在注意事项里写了“量纲不是货币金额，不能直接当作客单价使用”，但规则是数据里没有就不提交；同一道题的另一次运行正确地拒答了。

**被检查挡下的语句 5 条**，都是想看表结构（4 次查 `information_schema`，1 次 `DESCRIBE`），没有写操作。

## 口径配置没有测出差别

两份配置都是 48/48，按事先的约定，不能说“口径配置提高了准确率”。能观察到的差别只在过程上：

| | retail（现成的列和表达式） | retail_raw（只有文字口径） |
|---|---:|---:|
| 平均试几次查询 | 3.0 | 3.8 |
| 被退回的调用（48 次运行合计） | 2 | 7 |
| 平均用时（秒） | 19.3 | 22.9 |
| SQL 里原样用了配置里的表达式 | 44/48 | —— |

可能的解释有两个，这次分不开：一是文字口径对这个模型已经够用；二是题目太容易，两边都到顶了。

## 这个成绩不能说明什么

- **题目偏容易。** 100% 更像是题目没有把它难住，而不是它不会错。请求都写得很明确（指定了周、指标、排序），真实用户问得含糊得多。把含糊的问题变成明确的请求是原来那个 Agent 的事，要等接进去之后做端到端的评测才知道。
- 题目、参考 SQL 和查询 Agent 是同一个 AI 写的，可能有共同的误解。固定工具也能答的 12 道有独立核对，其余没有。
- 只有一张表，没有测多表关联；只测了一个模型，每道题 2 次。
- “算对”只说明数对。它写的口径说明、注意事项好不好，没有评。
- 拒答只有 3 道题、6 次运行，其中 1 次没有守住。样本太少，不能说它“知道什么时候该拒绝”。

## 成本

一次查询平均约 2 万 token、19 秒（电商），CSV 约 1.1 万 token、15 秒。电商的数据说明（19 列、9 个指标、5 条注意）占了提示词的大部分。

## 重现

```bash
uv run da-agent query "2011 年 11 月按星期几看，每天的 GMV 各是多少？"          # 电商（口径配置 retail）
uv run da-agent query "各访客类型的转化率" --data path/to/online_shoppers.csv   # 任意 CSV，不需要配置
uv run da-agent eval-query --split holdout --name <新名字>                      # 重跑留出题（调用真实模型）
```
