# Agent 自主搭看板：Online Shoppers 盲测评分表（M13d）

**冻结时间：2026-10-14，在第一次用真实模型运行之前提交。** 之后发现的评分问题另行记录，不改这一版。

这次盲测有两个目的：
1. 换一份性质不同的数据（网站访问会话，不是电话营销），再检验 Agent 能不能独立搭出口径正确的看板。
2. 检验 M13c 的通用改进在没见过的数据上是否起作用：月份按日历排、比率带分子分母、不断言一行代表什么（第 G 节）。

## 测试设置（盲测）

- 数据：UCI Online Shoppers Purchasing Intention（`online_shoppers_intention.csv`，12,330 行，18 列，CC BY 4.0）。
  一家电商网站一年内的访问会话，Revenue 表示这次会话是否成交。
- **Agent 拿到的只有 CSV**：没有语义标注、没有数据说明（UCI 页面只用来写这份评分表），列的含义只能从列名和取值判断。
- 读者和目标（每次相同）：电商运营负责人复盘网站访问的购买转化——整体转化怎么样、哪些访客类型、流量来源和月份转化更高，以及需要注意的数据问题。
- 模型：MiniMax-M3.1-Flash-Preview。计划跑 3 次；每次单独记录，结论写明样本量。

## 我先探查到的事实（写评分标准用）

| 事实 | 数字 |
|---|---|
| 整体转化率 | 15.47%（1,908 / 12,330） |
| 一行代表什么 | 数据说明：每行是一次会话，并且每次会话来自不同的用户。数据里没有编号列，Agent 无法验证 |
| 完全重复的行 | 125 行和其他行完全相同（`profile_table` 的 row_identity 会给出） |
| 月份没有年份，也不全 | 只有 10 个月，缺 1 月和 4 月；写法不统一（June 是全称，其余是缩写） |
| 各月样本量差很多 | 5 月 3,364 条、11 月 2,998 条；2 月只有 184 条（转化率 1.6%，3 单）、6 月 288 条 |
| 月份之间的转化率 | 11 月最高 25.35%（760 / 2,998），2 月最低 1.63%（3 / 184） |
| 编码的分类列 | OperatingSystems、Browser、Region、TrafficType 是整数编码，没有给出名称；求和、求平均没有意义 |
| 小样本的极端转化率 | VisitorType = Other 85 条（18.8%）；Browser 12 只有 10 条（30%）；TrafficType 16 只有 3 条 |
| PageValues 和成交本身相关 | PageValues 是“成交前访问过的页面的平均价值”（Google Analytics 按成交分摊）。PageValues > 0 的会话转化率 56.3%（1,538 / 2,730），等于 0 的 3.9%（370 / 9,600）；不能当成转化的原因或事前的筛选条件 |
| SpecialDay 不是计数 | 取值 0–1，表示离节日多近；只有 2 月和 5 月有非 0 值，和月份混在一起 |
| BounceRates、ExitRates 是每次会话的页面平均值 | 取值 0–0.2；求和没有意义 |
| 新访客转化更高 | New_Visitor 24.91%（422 / 1,694），Returning_Visitor 13.93%（1,470 / 10,551） |

## A. 能独立完成（全部满足才算“独立完成”）

## D. 数据陷阱（盲测的重点：没人告诉它）

| 编号 | 陷阱 | 算发现了的标准 |
|---|---|---|
| D1 | 月份没有年份、也不全 | notes 或 insight 写明没有年份，或缺 1 月和 4 月；或者不把月份写成增长、下滑这类趋势 |
| D2 | 编码的分类列 | 用了编码列时，写明编号没有名称（例如“流量来源 2”含义不明）；没用则不适用 |
| D3 | 小样本的极端转化率 | 对转化率特别高或特别低的小分组（2 月、Other、少见的浏览器和流量来源），写明样本量，或在 notes 提醒 |
| D4 | PageValues 和成交本身相关 | 用了 PageValues 时，没有把它写成转化的原因，并说明它和成交本身有关（例如是按成交计算的页面价值、属于事后数据）；没用则不适用 |
| D5 | SpecialDay 和月份混在一起 | 用了 SpecialDay 时，写明它只出现在少数月份或不是计数；没用则不适用 |

## E. 结论

| 编号 | 检查 |
|---|---|
| E1 | insight 没有因果表述（报告核查同一份词表） |
| E2 | insight 的数字都有出处（程序强制；记录被退回的次数和原因） |
| E3 | 最后的回答里数字都有出处 |
| E4 | 没有和数据不符的概括：写“越……越……”这类规律时，每个分组都要符合 |

## G. M13c 通用改进是否起作用（这次新增）

| 编号 | 改进 | 算起作用的标准 |
|---|---|---|
| G1 | 月份按日历排 | 按月份的图（条形图除外，条形图按数值排名）里，月份按 Feb → Dec 的日历顺序显示，包括写法不统一的 June |
| G2 | 比率带分子分母 | 至少一处 insight 或 notes 用了分子分母或样本量（例如“15.5%（1,908 / 12,330）”）；没有因为引用分子分母被退回 |
| G3 | 不断言一行代表什么 | 没有把对一行含义的猜测写成事实：例如“每行是一位用户”“同一用户多次访问会重复计入”“每行是一笔订单”。叫“会话数”“访问次数”“记录数”可以（列名描述的都是一次访问里的行为），但不对用户层面下结论 |
| G4 | 重复的行 | 记录 Agent 是否提到 125 行完全相同的记录；只记录，不评分 |

## F. 记录但不评分

模型调用次数、token、用时、工具调用次数、被退回的次数和原因、参数位置写错的次数（M13b 有 5 次）、程序本身的限制、Agent 没做但人会做的事。
