# 看板 Agent 和查询 Agent 共用口径配置：评分标准（M23）

**冻结时间：2026-11-22，在留出题上第一次运行之前提交。** 之后发现的问题另行记录，不改这一版，也不改题目。

## 要检验什么

M22 复核发现：查询 Agent 用口径配置里的表（`order_lines`，有新客 / 老客、周、月这些算好的列），看板 Agent 用的是 M13 的交易表（没有）。看板 Agent 不能写 SQL、只能对已有的列做聚合，所以“每周复盘新老客”的看板两次都没做到。

M23 让看板 Agent 也读口径配置（`semantic:retail`）：同一个数据库文件、同一张表；配置里每个指标多写了一份“看板写法”，测试核对它和查询 Agent 的 SQL 写法逐周、逐国家算出来一样；看板里和配置同名的指标，定义必须一致，否则退回。

这次评三件事：

1. **新老客看得到吗**：以前搭不出来的看板，现在能不能搭出来、并且真的按新客 / 老客拆开。
2. **口径一致吗**：用户点名要 GMV、客单价这些指标时，看板是不是按配置的口径算（叫什么名字都行）。
3. **没变差吗**：M22 能搭的看板照样能搭，只是提问的照样不搭。

## 题目（[dashboard_shared.yaml](dashboard_shared.yaml)）

- 4 道要看板、4 道只是提问：和 M22 的留出题一字不差（换了 id），用来和 M22 比较。
- 2 道新的要看板：“会员运营看每月新客、老客和新客来自哪些国家”（要用到 customer_type 和 country），“周会看板：每周 GMV、净销售额、订单数、客单价”（四个指标都要按配置口径）。
- 开发题 1 道（[dashboard_shared_dev.yaml](dashboard_shared_dev.yaml)），调通流程用，成绩不算数。

对比组只有一个：`agent_dashboard`（带流程 + 取数 + 搭看板，默认配置）。每道题跑 2 次，共 20 次运行。模型 MiniMax-M3.1-Flash（三个 Agent 相同）。

## 怎么算（程序判定）

和 M22 相同的部分：

- 要看板的题：必须**成功**调用 `build_dashboard`，回答里要出现 `dashboard.html`。
- 只是提问的题：不能调用 `build_dashboard`。
- 都要求正常结束、答案里的数字全部有出处。

新加的两条，看看板 Agent 最后一次通过检查的方案（一次回答搭了两个看板时，有一个满足就算）：

- `dashboard_columns`：方案里用到了这些列（指标的 column 或 where、图的横轴或分组、筛选器都算）。新老客两道题要求用到 `customer_type`，会员那道还要用到 `country`。
- `dashboard_metrics`：方案里有按口径配置算的这些指标。比较的是定义（聚合方式、列、配置里的筛选条件；比率逐个比较分子分母），不看名字。

## 结论的标准（运行前定下）

| 结论 | 要求 |
|---|---|
| 新老客看得到 | 两道新老客题共 4 次：看板搭出来并且满足 `dashboard_columns` ≥ 3 次（M22：0/2） |
| 口径一致 | 两道点名指标的题共 4 次：满足 `dashboard_metrics` ≥ 3 次 |
| 接得上 | 要看板的 12 次里，看板搭出来 ≥ 11 次 |
| 分得清 | 20 次里，该搭的搭了、不该搭的没搭 ≥ 19 次 |
| 没变差 | 20 次里按程序判定通过 ≥ 16 次（M22：13/16） |

- 全部达到：看板 Agent 默认用 `semantic:retail`（主 Agent 的 `build_dashboard`、界面）。
- “新老客看得到”没达到：说明共用口径没有解决这个问题，照实记录原因，先查原因再决定。
- “接得上”或“没变差”没达到：默认退回 M13 的交易表（`retail`），`semantic:retail` 保留为 `build-dashboard` 的选项。

另外照实记录（不设门槛）：

- 搭出来的看板逐个看一遍，标题和图是不是对着用户要的东西；新老客的看板是不是真的按新客 / 老客拆开（Claude 代项目作者判断，作者本人未逐条核对）。
- 同名指标定义不一致被退回了几次（新加的检查有没有在起作用、有没有误伤）。
- 每次运行的 token（含嵌套的 Agent）和用时，和 M22 比；主 Agent 写的目标超过上限被退回几次（M22：8 次里 5 次超过 300 字；这次上限 600 字，提示写“200 字以内”）。

## 已知的局限（运行前写下）

- 题目只有 10 道，每道 2 次；题目、提示词和口径配置是同一个 AI 写的。
- `dashboard_columns` 只能说明方案用到了这一列，不能说明用得对；对不对靠逐个复核。
- 新客的口径是“第一次购买落在当周”，按月看时一个客户的第一周跨月，会在两个月里都算新客；这是配置本来的口径，这次不改。
- 只用了电商数据；财报数据和用户给的 CSV / Excel 没有口径配置，仍走原来的路。
