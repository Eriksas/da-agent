# Agent 自主搭看板：真实模型评分表（M13）

**冻结时间：2026-10-14，在第一次用真实模型运行 `build-dashboard` 之前提交。** 之后发现的评分问题另行记录，不改这一版。

要回答的问题：给一份数据和一个读者，Agent 能不能**独立**搭出一个合格的看板，中间不需要人插手。

单次运行只能说明“这一次怎么样”，不是通过率；结论里必须写明样本量。

## A. 能独立完成（全部满足才算“独立完成”）

| 编号 | 检查 | 怎么判断 |
|---|---|---|
| A1 | 运行正常结束，提交的方案通过检查，生成了页面 | 运行状态 completed，有 dashboard.html |
| A2 | 没有超过工具调用上限（25 次） | 运行记录 |
| A3 | 先了解数据再设计：调用了 profile_table，加载了 dashboard-design 流程 | 运行记录里的工具顺序 |
| A4 | 放进看板的每张非 kpi 图，提交前都预览过（同样的类型、指标、横轴、分组） | 对照 preview_chart 和最终方案 |

## B. 口径

| 编号 | 检查 |
|---|---|
| B1 | 销售额类指标限定了 line_type = 销售（校验器强制；记录是否一次通过） |
| B2 | 订单数用 count_distinct(invoice)，不是 count 行数 |
| B3 | 取消没有被算进销售额；如果算净额，要说明 |

## C. 选图

| 编号 | 检查 |
|---|---|
| C1 | kpi 2–4 张，图一共 6–9 张（分析流程的建议） |
| C2 | 至少一张随时间变化的图，至少一张类别排名或构成图 |
| C3 | 每张图的 why 写了它回答的业务问题（人工判断，不是套话） |

## D. 数据陷阱（程序会在 notes 里标出，看 Agent 有没有处理）

| 编号 | 陷阱 | 算处理了的标准 |
|---|---|---|
| D1 | 2011-12 只有 8 个交易日 | insight 或 notes 写明，且没有拿它和完整月份比 |
| D2 | 英国占 GMV 的 85% 以上 | 用 keep 分开、另放一张只看海外的图，或在 insight 里写明占比 |
| D3 | 销售按下单口径，包含之后被取消的订单 | 放了取消金额或取消率，或在 notes 里说明 |
| D4 | 约 22% 的行缺客户 ID | 有按客户统计的指标时，notes 写明会偏少；没有这类指标则不适用 |

## E. 结论

| 编号 | 检查 |
|---|---|
| E1 | insight 没有因果表述（用报告核查同一份词表：导致、因为、由于……） |
| E2 | insight 的数字都有出处（程序强制；记录被退回的次数和原因） |
| E3 | 最后的回答里数字都有出处（报告核查） |

## F. 记录但不评分

模型调用次数、token、用时、工具调用次数、被退回的次数和原因、Agent 没做但人会做的事。
