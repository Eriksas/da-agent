# Agent 自主搭看板：表达能力评分表（M13e）

**冻结时间：2026-10-14，在第一次用真实模型运行之前提交。** 之后发现的评分问题另行记录，不改这一版。

## 要检验什么

用户反馈：Agent 搭的看板每次都是同样的视觉方案（指标卡 + 条形图 + 表格）。原因主要在程序：一张图只能放一个指标，所以“规模 + 比率”只能做成表格；图上没有参考线和重点；布局固定。M13e 增加了 scatter、数值分段（bins）、整体参考线（reference）、重点（highlight）、分区（section）和宽窄（width），并在分析流程（SKILL.md v3）里写了按问题选图的规则。

这次检验 Agent 会不会用这些新能力**把图做得更贴合问题、更有重点**，不是看图型越多越好。

## 测试设置

- 数据和读者都和之前的盲测相同，方便对比：
  - Online Shoppers（3 次）：电商运营负责人复盘网站访问的购买转化：整体转化怎么样、哪些访客类型、流量来源和月份转化更高，以及需要注意的数据问题。
  - Bank Marketing（2 次，检验换一份数据是否同样有效）：营销负责人复盘这轮电话营销：整体转化怎么样、哪些客群和渠道转化更高，以及需要注意的数据问题。
- 同样只给 CSV，没有语义标注和数据说明。模型：MiniMax-M3.1-Flash-Preview。几次运行之间程序不改。

## 改进前的基线（M13b、M13d 的 6 次运行）

| 项目 | Bank（3 次） | Shoppers（3 次） |
|---|---|---|
| 表格 | 2、4、2 张，全部是“数量 + 比率” | 2、1、2 张，全部是“数量 + 比率” |
| 比率对比图（bar、column） | 3、2、3 张，都没有参考线（当时没有这个能力） | 3、3、2 张，同上 |
| 有 insight 的图 | 都没有重点（当时没有这个能力） | 同左 |
| 分区 | 没有 | 没有 |
| 非 kpi 的图型 | bar + heatmap + table；bar + table；bar + column + heatmap + table | bar + column + table；bar + column + table；column + heatmap + table |

## V. 表达能力（这次的重点）

| 编号 | 检查 | 达标 |
|---|---|---|
| V1 | 规模和比率一起看时用 scatter，不用“数量 + 比率”的表格 | “数量 + 比率”的表格为 0 张；表格最多 1 张，且只用来查明细 |
| V2 | 比率、平均值的对比图（bar、column，非时间横轴）有整体参考线 | 这类图里 ≥ 80% 有 reference |
| V3 | 有 insight 的 bar、column、scatter 有重点，并且重点就是 insight 说的分组 | 这类图里 ≥ 80% 有 highlight，且 highlight 的分组在 insight 里提到（名称或明显的对应说法，人工核对） |
| V4 | 分区合理 | 6 张以上非 kpi 的图时分了 2–4 个区，同一区的图回答同一类问题（人工判断） |
| V5 | 新能力没有被误用 | scatter 的两个轴有意义（规模 vs 比率，或两个可比的指标）；bins 的分界点合理（没有一段占 80% 以上，也没有被分界点切出的空段）；highlight 没有和 insight 矛盾（人工判断） |

**整体判断**：Shoppers 3 次和 Bank 2 次里，V1–V3 都达标的次数 ≥ 4 次，并且 V5 没有误用，算“表达能力提升且用对了”。

## 记录但不评分

- 用了哪些图型（种类数）、有没有用数值分段、半宽的图有几张。
- 截图的人工观感：每张图是否一眼能看出结论说的那件事。
- 模型调用次数、token、用时、被退回的次数和原因（尤其是新字段写错的次数）。
- 一个限制要写明：分析流程里明确写了这些规则，所以“用了新能力”有一部分是在照着规则做；评分时看的是用得对不对。
