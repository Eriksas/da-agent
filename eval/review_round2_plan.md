# 复核 Agent 第二轮评测：计划（M17）

**写于 2026-11-11，在多模型对比（M16）的运行还没有结束、任何新答案都还没有看过的时候提交。** 第一轮的评分表 [review_rubric.md](review_rubric.md) 和[补充说明](review_rubric_addendum.md)继续有效，这里只写这一轮新增的内容。

## 要检验什么

第一轮的结论：复核 Agent 指得出植入的错误，但它在原样答案上说的“错误”只有 67% 成立（6 条里 4 条），没有达到 70%，所以没有接入报告。
第一轮之后有两个想法，都是看了结果才想到的，必须换一批没用过的答案来检验：

1. **复核两次，只保留两次都指出的**：第一轮里重复出现的 3 条“错误”意见全部成立。
2. **换一个模型来复核**：两个模型的盲区可能不同。

## 材料（按规则机械地选，不挑）

- 写答案的模型：Flash（项目实际在用的）。答案取自 M16 这次新跑的评测 `models-2026-11-11-flash-{cases,holdout,company}`。
- 每道题取 `agent_skill-1`；如果它不满足“正常结束、自动评分通过、数字全部有出处、至少 2 次工具调用”，改取 `agent_skill-2`；两个都不满足就跳过这道题。
- 再加 4 份第一轮没用过的自动周报：2010-W02、W03、W04、W08。
- 这些就是“原样答案”。按题目顺序（原题、留出题、财报、周报）取前 12 份，用第一轮的四种方式各植入一处错误；植入的代码不改。
- 这批答案的题目和第一轮有重叠（同一批题），但答案是新生成的，复核 Agent 的提示词在第一轮之后没有改过。

## 每份材料复核三次

| 代号 | 复核模型 |
|---|---|
| F1 | Flash，第 1 次 |
| F2 | Flash，第 2 次（独立运行） |
| M | MiniMax-M3 |

## 四种用法

| 用法 | 一条“错误”意见算数的条件 | 植入的错误算“指到了”的条件 |
|---|---|---|
| A 单次（重复第一轮） | F1 提出 | F1 有意见落在被改的那一句 |
| **B 两次取交集（主要检验对象）** | F1 提出，并且 F2 在同一句也有一条“错误”级意见 | F1 和 F2 都有意见落在被改的那一句 |
| C 换模型 | M 提出 | M 有意见落在被改的那一句 |
| D 两个模型取交集 | F1 提出，并且 M 在同一句也有一条“错误”级意见 | F1 和 M 都有意见落在被改的那一句 |

“同一句”指两条意见引用的原文落在同一个句子里（按句号、分号、换行切分，和第一轮评分用的切法相同）。
“分不清”的规则同第一轮：原样答案的同一次复核里，这一句本来就被指出过的，不计入。

## 人工判断

- 把 F1、F2、M 在原样答案上的全部“错误”级意见合在一起，按句子去重，逐条回到工具结果验算：成立 / 有争议 / 不成立，标准同第一轮。
- **判断时不看这条意见是谁提的**：先生成一份不带来源的清单，判断完再和来源对上。
- 由 Claude 代项目作者判断（作者授权，本人未逐条核对）。

## 结论的标准（运行前定下）

沿用第一轮的两条标准：

| 用途 | 要求 |
|---|---|
| 作为报告里的“复核意见”给人参考 | 植入错误的检出率 ≥ 70%，并且原样答案上算数的“错误”意见至少 70% 成立 |
| 自动把意见退回给写答案的 Agent 修改 | 检出率 ≥ 85%，并且至少 90% 成立 |

- **只有 B 的结果用来决定是否接入报告。** B 达到第一条：把“复核两次取交集”做成默认做法，接入报告。B 没达到：维持现状（只保留命令）。
- A、C、D 只记录。即使 C 或 D 达标而 B 不达标，也不接入：那是事后挑出来的，要再换一批答案检验。
- 某种用法在原样答案上算数的“错误”意见少于 5 条时，比例没有意义，记为“样本不足”，不算达标。

## 已知的局限（运行前写下）

- 取交集会让意见变少：成立的比例可能上去，但真正的错误也会被漏掉更多。所以同时报告每种用法保留了多少条成立的意见。
- 两个模型来自同一家厂商。
- 成本是单次复核的 2–3 倍，会一并报告。
- 判断“成立 / 不成立”的仍然是设计评测的同一个 AI。
