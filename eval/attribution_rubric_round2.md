# 数字归属核对：第二轮的评分标准（M18）

**冻结时间：2026-11-16，在留出集 C 上运行之前提交。** 第一轮的标准（[attribution_rubric.md](attribution_rubric.md)）不改；这里只写第二轮不同的地方。

## 为什么有第二轮

第一轮在留出集 A、B 上没有达标（[结果](results/attribution-2026-11-15/summary.md)）：原样答案上 8 条“对象”标记，没有一条成立；“含义”提示 22/26（85%）成立，低于 90%。

按第一轮的标准，跑完就不能再改规则，要改得另找一批没用过的答案。第二轮就是这样做的：只做这一轮，不达标就停。

## 规则改了什么

都是按第一轮误报的原因改的结构性规则，不针对某一句（[attribution.py](../src/da_agent/attribution.py)）：

1. 名字只往前找到上一个数字为止。
2. 数字后面 14 个字符以内出现它自己的名字，不标记。
3. “占总变化的比重”这类数不查对象（只要有一处出处是占比）。
4. 有效数字不到 3 位的数不查对象。
5. 反引号里的文字不当名字（工具名 `decompose_gmv` 不是在说 GMV）。
6. “含义”提示：这一行出现“总变化、抵消、抵掉、share”也算说明了是占比。

试过、没有采用的：让冒号或括号不再断句。在开发材料上多指到 3 条植入的错误，但原样答案上的“对象”标记从 0 条变成 5–12 条，都不成立。

## 材料

- **开发材料（dev2，108 份）**：第一轮的开发集 23 份 + 留出集 A 16 份 + 留出集 B 69 份。A、B 的结果已经看过，规则是照着它们改的，**成绩不算数**。
  改完后在这 108 份上：植入的对象替换指到 29/50（58%），数字对调 18/58；原样答案上“对象”标记 0 条，“含义”提示 23 条。
- **留出集 C（159 份）**：多模型对比（M16）同一批评测里其余对比组的运行（`agent-1`、`agent-2`、`agent_skill-2`），三个模型各 53 份。按规则机械地取（正常结束、有答案的），两轮调规则时都没有在它们上面跑过。给 Flash 的 53 份植入错误；另外两个模型的只看会不会乱报。

C 的局限：题目和 B 是同一批（同一道题的另一次运行），答案的文字是新的，但问题不是新的。

## 结论的标准

和第一轮相同，不放宽：

| 用途 | 要求（都在留出集 C 上算） |
|---|---|
| “对象”标记接入核查结果和报告（只标记，交给人看） | 原样答案上的“对象”标记 ≥ 5 条时至少 80% 成立；少于 5 条时不成立的不超过 1 条。并且植入的“对象替换”检出率 ≥ 60% |
| “含义”提示接入报告 | 提示至少 90% 成立 |

补充两点（运行前写下）：

- 开发材料上的检出率是 58%，低于 60%。留出集上达不到也不意外；达不到就按没达标处理。
- 如果原样答案上一条“对象”标记都没有，上面第一条按字面算通过，但那只说明“没有乱报”，不说明“标出来的是对的”。这种情况在结论里照实写。

留出集 C 只跑一次。**不达标就停**：功能留作命令行里的实验性检查，不接入报告，不再有第三轮。

判断“成立 / 不成立”的仍然是 Claude（代项目作者，作者本人未逐条核对），依据留在结果目录里。
